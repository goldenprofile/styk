# Сопоставление с Codex и Claude Code

Сводка обсуждения по официальной документации, проверенной 2026-11-13. Рассматриваются публичные возможности, а не недокументированные внутренние детали. Доступность зависит от версии и среды.

## Вывод

Оба инструмента предоставляют агентное исполнение, делегирование и управление контекстом. Наша система добавляет авторитетное состояние workflow, приёмку результатов, последовательную запись, общие бюджеты и проверяемое восстановление.

## Сопоставление

| Область | Наша система | Codex | Claude Code |
|---|---|---|---|
| Управление | Supervisor и программный runtime | Главный агент и агентные потоки | Главная сессия и subagents |
| Роли | Ограниченные задания | Пользовательские профили агентов | Профили с инструментами и настройками |
| Состояние | Задачи, попытки, снимки, доказательства | Продолжение и возобновление threads | Сессии и checkpoints |
| Контракт успеха | Проверка runtime | Требует нашей приёмки | Требует нашей приёмки |
| Интеграция | Backend adapter | SDK / App Server | Agent SDK / программный CLI |

Codex поддерживает управление жизненным циклом исполнителей и специализированные роли. Claude Code предоставляет subagents с отдельным контекстом, промптом и инструментами. Это позволяет использовать готовую механику вместо собственной реализации agent loop. [Codex Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Claude Code Subagents](https://code.claude.com/docs/en/sub-agents)

## Контекст и глубина

У Claude Code обычный subagent начинает с отдельного контекста, fork наследует беседу. Вложенное делегирование поддерживается; `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` ограничивает его одним слоем. У конкретного воркера можно убрать `Agent`. Для переносимости собственный scheduler должен контролировать создание исполнителей. [Claude Code: subagents](https://code.claude.com/docs/en/sub-agents)

Два уровня — наша выбранная политика, а не универсальное свойство этих продуктов.

## Состояние и восстановление

Codex SDK запускает, продолжает и возобновляет потоки. Claude Code checkpoints сохраняют поддерживаемые правки и состояние беседы. [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk), [Claude Code Checkpointing](https://code.claude.com/docs/en/checkpointing)

Сессия хранит историю работы, а наш workflow — версию задания, зависимости, проверки и условия повторения. Возобновлённый разговор не подтверждает согласованность проекта. Нужно хранить и provider session ID, и собственные run/task/attempt ID.

## Полномочия

В актуальной документации Codex subagents наследуют sandbox и разрешения родителя. Custom agent не создаёт собственную read-only sandbox; соответствующая инструкция сама по себе не обеспечивает запрет записи. [Codex Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)

Claude Code позволяет настраивать инструменты и permission modes subagents; отдельно существует Bash sandbox. Runtime должен проверять реальную доступность требуемой изоляции и отклонять конфигурацию, которая её не обеспечивает. [Claude Code Subagents](https://code.claude.com/docs/en/sub-agents), [Claude Code Sandboxing](https://code.claude.com/docs/en/sandboxing)

## Конкурентность

Claude Code поддерживает `isolation: worktree`. Но runtime всё равно определяет базовую ревизию, владельца изменений, интеграцию и итоговые проверки. [Claude Code Subagents](https://code.claude.com/docs/en/sub-agents)

Agent Teams — дополнительная модель координируемых сессий, более свободная, чем наше минимальное ядро. Документация отмечает экспериментальный статус и ограничения восстановления, актуальности статусов и завершения. Для v1 достаточно обычных исполнителей и одного writer. [Claude Code Agent Teams](https://code.claude.com/docs/en/agent-teams)

## Проверки и события

Claude Code hooks дают точки запуска программных обработчиков вокруг инструментов, subagents и завершения задач. Codex App Server предоставляет события, историю и обработку подтверждений; SDK подходит для автоматизации. [Claude Code Hooks](https://code.claude.com/docs/en/hooks), [Codex App Server](https://learn.chatgpt.com/docs/app-server)

Наш ImplementAndVerify остаётся внешним автоматом: вызов исполнителя → сверка дерева → обязательные проверки → классификация → принятие, повтор, блокировка или остановка.

## Структурированный вывод

Claude Code CLI поддерживает JSON, stream-json и JSON Schema. Схема подтверждает форму результата; runtime отдельно проверяет артефакты, diff и тесты. Завершение потока Codex также не равно автоматической приёмке задачи. [Программный запуск Claude Code](https://code.claude.com/docs/en/headless)

## Граница реализации

Готовое: модель, agent loop, контекст сессии, доступные механизмы разрешений, события и редактирование.

Своё: задания, зависимости, состояния, артефакты, блокировка записи, критерии приёмки, лимиты, повторы и восстановление.

Начать с одного backend и полного сценария. Добавлять второй после стабилизации переносимого контракта.
